# KaiHei 开黑：北美游戏陪玩平台（第一版）

面向北美华人，同时支持外国玩家的游戏陪玩平台。第一版只做 **Valorant** 和 **CS2**。界面支持中文和 English，右上角一键切换。

> “KaiHei”是暂定名，以后想换名字，改 `public/index.html`、`public/app.js` 里的文字和 `public/icon.svg` 就行。

## 功能

**玩家（买家）**
- 注册：用户名、邮箱、密码、生日（**必须年满 18 岁**，按完整生日计算），并勾选同意平台规则
- 找陪玩：按游戏、语言（普通话、英语、粤语）、类型（技术陪玩、娱乐陪玩、教学）、价格、是否在线筛选；排序方式有推荐、评分、价格和最新
- 陪玩师主页：段位、每款游戏的价格、介绍、评分和评价
- 下单：选游戏和小时数，可以留言 → 付款（**目前是测试支付**）
- 订单页：进度条、订单内聊天（每 4 秒自动刷新）、**接单后**双方的 Discord 才互相可见，可以一键复制
- 确认完成、申请售后、给陪玩师打 1–5 星评价、举报

**陪玩师**
- 申请入驻：头像、昵称、介绍，每款游戏的段位和每小时价格（$3–$200），语言、类型、服务器地区（美西、美中、美东），Discord 用户名
- 资料审核通过后才会出现在首页
- “我现在在线”开关：6 小时后自动关闭，避免忘记关
- 接单或拒单、标记已完成
- 收入面板：已结算和进行中的收入（已扣平台服务费）

**钱怎么走（托管）**

| 情况 | 结果 |
|---|---|
| 买家付款 | 钱由平台托管 |
| 陪玩师 24 小时内没接单 | 自动全额退款 |
| 接单前买家取消，或陪玩师拒单 | 全额退款 |
| 陪玩师标记完成后，买家确认 | 结算给陪玩师（扣除 15% 服务费） |
| 标记完成后 48 小时买家没操作 | 自动确认 |
| 买家申请售后 | 客服在后台判定退款或结算 |

**后台**（`ADMIN_USERS` 里的用户进入“我的 → 后台管理”）
- 审核陪玩师申请：通过，或拒绝并填写原因
- 处理售后：退款给买家，或结算给陪玩师
- 处理举报：关闭，或封号（封号后立刻退出登录，陪玩主页下架）
- 暂停或恢复陪玩师；查看总用户数、订单数、成交额、平台收入

**平台规则**（注册时必须同意，`#/rules` 页面可以查看）：只做陪玩，禁止代练、共享或买卖账号；禁止线下见面和擦边服务；禁止私下转账。

## 运行

```bash
cd kaihei
npm install
ADMIN_USERS=你的用户名 npm start   # 打开 http://localhost:3001
npm test                           # 运行接口测试
```

不设置 `DATABASE_URL` 时，数据存在 `kaihei/data/` 文件夹；设置后存进 Postgres。

| 环境变量 | 说明 |
|---|---|
| `ADMIN_USERS` | 管理员用户名，多个用逗号隔开。先用这个用户名注册，再设置这个变量 |
| `DATABASE_URL` | Postgres 地址（Neon）。可以和 trove 共用同一个数据库，表名不同，互不影响 |
| `FEE_RATE` | 平台抽成，默认 `0.15` |
| `PORT` | 端口，默认 3001 |

## 放到网上

和 trove 一样用 Render + Neon，步骤见仓库根目录的 [DEPLOY.md](../DEPLOY.md)。仓库里的 `render.yaml` 已经加好了一个叫 **kaihei** 的服务（`rootDir: kaihei`）。在 Render 上同步 Blueprint 时，需要填写 `DATABASE_URL` 和 `ADMIN_USERS`。

## 结构

```
server.js          启动入口
src/core.js        业务逻辑：账号、陪玩师、订单状态、聊天、评价、举报、后台
src/messages.js    中英文错误提示
src/app.js         服务器（Express）：照片保存、把 /api 交给 core
src/store.js       数据存储：本地 JSON 文件，或 Postgres
public/            前端（原生 JS 单页应用，中英文切换）
test/              接口测试
```

## 正式收钱之前必须做的事

1. **接入 Stripe Connect**：买家付款走 Stripe，支持信用卡、Apple Pay、支付宝和微信支付；陪玩师用 Stripe Express 账户收款，1099 税表也由 Stripe 处理。代码里每个订单已经有 `payment: { provider, status: held | released | refunded }`，接真支付时，把“测试支付”换成 Stripe 的 PaymentIntent（手动扣款或延迟转账）就行。**先问 Stripe 能不能接陪玩类业务**，再开始写。
2. **注册公司**（比如 LLC），写用户协议和隐私政策。
3. **邮箱验证和找回密码**（需要 SendGrid、Resend 之类的发信服务）。
4. 用户多了以后，把数据从“一整份 JSON”拆成正式的数据表（和 trove 的限制一样）。
